# 历史研究验证与冻结实验

当前方法SAVED_SIGNAL_VALIDATION_V3回答已保存规则触发后的收盘表现，不模拟下单、成本、滑点或可成交性。GET统计只读；保存实验必须显式POST。

历史信号页默认展示“历史规律验证”，读取已有逐日重建任务的真实日期、行情天数、五条技术规则及5/10/20日样本；已有结果时新建表单默认折叠，刷新不计算。“已保存信号”另列实际保存的记录，不把两年K线当作两年已保存信号。六位股票代码可自动补交易所，错误输入会提示；版本从已有记录选择，混合版本、未成熟窗口等原因直接展示。未提交的输入明确标注，避免将上一只股票结果误认作本次查询。历史验证结果按任务日期冻结，不因顶部日期变化冒充最新结果。

验证证券下拉框读取当前用户启用的自选股，支持搜索；默认选择当前列表中的股票，不再固定胜宏科技或只列旧任务成员。“刷新自选与记录”同步关注范围和验证记录。切换股票时只展示该股对应结果；当前记录不包含该股时会查找已加载的匹配验证，仍未覆盖则显示“准备本股验证”，明确预填该股后再由用户提交。自选为空时引导添加股票，不回退到示例证券。旧验证的成员、日期和证据不随自选修改而覆盖。

## 成熟样本与版本

只使用明确TRIGGERED的真实记录，按权威日历确定后5/10/20个交易日。窗口须成熟、原价及同源因子连续；同规则同窗口按时间排除重叠，不把数据库相邻行当连续交易日。缺基准时不按0收益计算，保留股票样本数和对齐基准样本数。

较早区间的收益必须在较晚留出首日之前成熟。默认约70%/30%的日期分割可以事先指定，实验保存后冻结；选择多个实验中表现最好的一份仍有选择偏差，留档不证明方法有效。默认20个样本仅为小样本提示阈值。

新规则证据保存实际参数。相同版本名但阈值不同，按版本@参数指纹分别识别，默认不混算；页面可输入明确版本指纹。旧记录没有实际参数时只保留其原版本标识，不套用当前阈值。

## 两种可用时点模式

- RETROSPECTIVE使用当前已保存版本回顾历史，可能包含后补与供应商修订，不能宣称当时可得。
- POINT_IN_TIME从不可变行情/因子与规则修订重建每个交易日结束前最后已保存的值，保留修订ID。行情同时要求真实入库和采集时刻不晚于该日结束；权威日历也核对版本保存时刻。

规则修订由计算事务自然追加，同时保存当次阈值；同内容重算不反复追加，内容A→B→A会保留三个真实转换。新RAW_V2行情归档用数值字符串避免MySQL JSON浮点规范化影响DECIMAL精度，读取时由明确字段类型恢复。旧修订没有recorded_at时保持未知，不从供应商时间倒填，也不凭当前行推造历史版本。

这仍是收盘到收盘描述统计：信号日盘后才产生的研究结果，不能假定按当天收盘价成交。不同规则之间相关性、当前自选的幸存者偏差及未保存的早期证据仍影响结论。

## 保存、复算和完整性

历史信号页可显式保存完整实验，包含原始请求、原价/同源因子、修订ID、规则证据和实际阈值、权威开市日期、分割条件、方法版本及结果。捕获在一致读事务内完成；输入上限32MiB，过大时缩小日期范围。

实验输入和结果以精确JSON文本保存，不依赖MySQL对JSON数字的规范化；分别保存语义SHA256。应用只有新增和读取入口，无覆盖/删除方法。复算只读取冻结输入，不访问当前行情、当前规则或上游；指纹不一致会拒绝读取/复算，方法版本不匹配也不静默套用新算法。

当前配置清单和阈值作为capture时元数据单独保存，不冒充旧规则参数；实际历史阈值来自相应规则修订。模拟模式不能保存真实研究实验，但可读取已有实验。完整接口见[REST API](../api/endpoints.md)。


## 执行一次真实研究验证

在“历史信号”页“历史规律验证”展开“新建或更新区间验证”，选择起止日期、类型和已启用自选。提交后立即返回持久任务，页面轮询轻量进度，支持取消、再次查看和完整证据下载。刷新或切换统计窗口不启动计算。模拟模式禁止提交真实验证，但可以查看历史记录。

也可在真实后端运行时使用：

```bash
bash scripts/tools.sh validate-research 2024-10-14 2026-10-30
bash scripts/tools.sh validate-research 2024-10-14 2026-10-30 technical
bash scripts/tools.sh reproduce-research-validation
```

范围为all、technical或market，缺省all。CLI先提交后台任务，轮询状态，成功后显式下载并导出当前唯一artifacts/research-validation.md及.json，不调用行情上游、不改写业务信号、不创建数据库备份。中断CLI只结束等待，后台任务可在页面继续查看或取消。重复的活动条件返回原任务，终态后可明确提交新任务。

### 一致计算与完整复算

RESEARCH_AUDIT_V2从价格、因子、市场日历、同源停牌日期及冻结阈值重建：

1. 检查原始输入文本SHA256和支持的协议/技术算法版本。
2. 用生产唯一TechnicalEvidenceCalculator生成逐日指标，按HALF_UP统一均线4位、RS及量比8位，并核对指标层指纹。
3. 使用冻结规则生成逐条评估，核对规则层指纹，不把已生成信号当复算起点。
4. 按成熟交易日、非重叠和70%/30%日期区间计算统计，核对结果指纹。

各规则按自己的最短窗口核验缺口；不再统一要求61天才能评估短期规则。股票应有日期只排除同源证据确认的停牌，收益窗口仍使用权威市场交易日。ADJ_V2 / RULE_V2 / TECHNICAL_V2明确新口径；旧报告和旧算法证据不覆盖。旧RESEARCH_AUDIT_V1不能静默用V2重算，V3已保存信号统计协议仍独立维护。

十年上限针对研究区间，固定四个月预热另行加载，并在结束日一次选择整段来源，不靠分段跨源拼接。请求接收时冻结范围、证券和参数，实际行情在执行时用一致读捕获；捕获完成后释放数据库事务，再执行逐日计算和序列化。当前保存版本回顾不证明历史当时可得。

### 后台执行与资源边界

独立单消费者和控制线程负责验证，心跳不代表计算进展。取消先持久保存，最终发布SQL同时检查归属、停止意图和截止，取消或超时不会保存成功证据。排队取消直接终止；运行中为协作中断，底层SQL仍受超时约束。进程失联默认120秒后归为中断并保留取消/超时意图，排队任务继续保存。

默认最多10只自选、20个活动任务、50000条重建评估、32MiB完整证据，执行截止15分钟。一致读捕获超时120秒。超限须减少范围，不通过截断伪造完整结果。状态列表不加载摘要和原价；详情只加载轻量统计，完整证据仅显式下载并核对指纹。

### 结论范围

已有信号分别核验当前版本回顾和严格时点；逐日重建仅涵盖五条技术规则，不借用今天财报、主题或持仓重建过去。完整全A检验仅使用当前模型合格完整评分，与未来5/10/20日沪深300表现配对，计算秩相关和固定高低分组收益差。没有完整评分时配对为0、相关为空。

复算一致只证明冻结证据可重建。当前自选有选择及幸存者偏差，阈值可能受历史启发，较晚区间不能包装成未经接触的独立样本外实验；风险规则触发后上涨不代表提示有效，正收益比例不是策略胜率。单区间20样本只是小样本提示，不是效果认证。模型有效性仍需预先固定方案后的独立数据检验，并考虑成本及可成交性。


## 组合策略执行扩展

新提交验证使用 `PRICE_VOLUME_EXECUTION_V3`。收盘核对两月量价方案，下一市场交易日开盘尝试执行。明确减仓信号触发减仓，收盘触发原方案风险线或当日结构止损时尝试完全退出。全区间、较早区间、较晚留出分别独立起仓，沿用现有策略参数。

固定模拟资金10万元，建仓与加仓各按初始资金25%，减仓50%；100股整手，佣金双边万三、最低5元，卖出印花税万五，单边滑点万五，成交额参与不超过1%。这些是透明执行假设，不是个人仓位建议。单价日与开盘相对前收涨跌达4.5%的日期保守跳过，并报告跳过次数；没有历史ST、精确涨跌停或盘口资料，不能据此证明其他日期必能成交。

持仓期间因子变化时，按冻结的公司行动公告与同源因子处理。缺少可靠公司行动、应有日线或合格价格时，区间收益、回撤与胜率留空。区间末仓位按最后收盘估值，末日挂单不计为成交，基准不完整时留空。

已平仓胜率等于扣费后盈利的完整持仓周期数除以全部完整平仓周期数。分批成交的费用和已核验权益计入该周期盈亏，末期未平仓和未成交委托不计入胜率。各股票独立模拟，任务摘要按平仓笔数汇总。策略结果与指纹存入任务，原 V1、V2 结果继续按各自版本复算。

历史信号页的新建验证支持填写共用账户本金，默认 50,000 元。量价规则使用同一现金余额，下一交易日开盘先处理卖出、再处理买入。同向委托按证券代码排序。单股仓位上限为账户权益的 25%，包含买卖费用的估计止损风险上限为账户权益的 1%。共用账户结果随本次任务冻结，可从各股票的冻结输入重新计算。

`PRICE_VOLUME_SHARED_CASH_V3` 的报告在每个区间对比同股持有。对照使用相同起点和本金，为每只证券平均分配初始资金。在首次满足模拟成交条件的开盘买入，余款留作现金，期末统一按收盘估值。买入持有没有止损仓位约束，遇到无法成交或不够一手时保留现金，页面显示实际买入的证券数量。持仓期间缺少公司行动证据时，该区间保留具体缺项，无法计算净盈亏差额。

“规则对照与逐笔结果”可查看完整平仓净盈亏、信号和执行日期、成交费用及跳过原因。成交额对照只在原建仓条件上增加最近 5 日平均成交额至少等于此前 20 日均值这一项，原加仓、减仓与退出条件照常执行。三种区间各自从初始资金起跑。旧版本使用各自冻结协议复算。

`PRICE_VOLUME_SHARED_CASH_V4` 增加“中期逐股独立回放”。每只证券的原回踩方案与顺趋势候选分别以提交的本金独立起跑。顺趋势候选要求最近两个交易日的收盘各自不低于当日 MA60，且 MA60 不低于五个交易日前。收盘先核对趋势，随后按次日开盘分别记录是否成交以及一手金额、账户仓位额度和估计止损预算。统计覆盖完整区间，执行明细展示最近 40 条。候选用于研究比较与个股观察，原回踩方案仍用于原研究计划。


## 导出已完成验证

```bash
bash scripts/tools.sh export-research-validation 5
```

只读指定任务，核对完整证据 SHA256 并离线复算，替换唯一的 `artifacts/research-validation.md` 和 `.json`。Markdown 列出各区间的扣费收益、已平仓胜率、最大回撤、基准、卖出与跳过次数。仅成功且证据一致的任务可以导出。

本机工具默认访问http://127.0.0.1:5173；仅启动原生后端时，在本机配置ALPHASCOPE_API_BASE=http://127.0.0.1:8080。只接受无凭据的回环地址，不用于绕过PUBLIC登录或数据授权。
