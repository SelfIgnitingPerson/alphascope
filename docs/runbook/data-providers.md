# 行情来源与数据质量

行情在 Java 后端内接入，不需要额外语言解释器。配置变量集中见[配置说明](configuration.md)，首次启动见[项目首页](../../README.md)。这里说明通道能力、原价/因子和缓存规则。

## 通道能力

| 通道           | 个股原价/因子 | 沪深300                       | 日历              | 沪深截面           | 市场复权事件 | 要求                                 |
| -------------- | ------------- | ----------------------------- | ----------------- | ------------------ | ------------ | ------------------------------------ |
| 交易所公告日历 | 不支持        | 不支持                        | 已核验2024—2026年 | 不支持             | 不支持       | 固定官方年度通知、周末规则及资源指纹 |
| BaoStock       | 支持          | 支持，含成交额                | 支持              | 支持               | 支持         | 免费公开服务，受限时停止访问         |
| 新浪           | 支持          | 不启用，缺可靠成交额          | 支持              | 不支持             | 不支持       | 免费公开接口                         |
| 东方财富指数   | 不支持        | 仅000300.SH真实日线，含成交额 | 不支持            | 不支持             | 不支持       | 公开接口，PUBLIC仍需有效使用许可     |
| Tushare        | 支持          | 支持                          | 支持              | 支持历史清单与截面 | 支持         | Token及各接口权限                    |

默认顺序为交易所公告日历 → BaoStock → 新浪 → 东方财富指数 → 已配置的Tushare，先按能力过滤再尝试；指数专用源不会被当作个股或日历来源。单独选择新浪无法完成依赖沪深 300 的整套日报；指数主通道失败且没有其他可用指数来源时，任务明确失败。

默认配置：

```dotenv
MARKET_PROVIDER=multi
MARKET_CHANNELS=exchange-calendar,baostock,sina,eastmoney,tushare
TUSHARE_TOKEN=
MARKET_CACHE_MINUTES=1440
```

未配置 Token 时多通道跳过 Tushare。演示必须明确选择 `demo`；真实通道失败不会自动回退到演示。当前能力为收盘后历史日线，不是盘中 Tick 服务。

## 数据质量与缓存

1. 一个标的、一个完整分析窗口只采用一家供应商；原价与因子必须同源。
2. 对照权威日历逐个交易日核对。已知上市日期之前的区间、BaoStock 证实的停牌可以排除；未知缺口、缺因子、异常 OHLC 或陈旧响应都拒绝。
3. 缓存逐行检查采集时间、来源和因子，不因首尾日期齐全就忽略中间缺口。普通缓存默认有效期 24 小时。对已结束业务日，过期的真实历史版本通过完整交易日集合、同源有效因子、OHLC、成交量额与采集时间检查后，允许补跑；报告标明使用已存版本及其原采集时间，未联网核验供应商最新修订。当天、未来日期、缺失交易日或无效数值不能走历史补跑。设 `MARKET_CACHE_MINUTES=0` 仍强制重采。
4. 自选与基准同步两年历史；仅用于同业计算的成员同步最近 140 个日历日，为 60 日收益及近期指标保留预热。历史补跑不改写原行情、因子、批次或采集时间，不能据此声称已恢复上游访问或已完成严格时点回测。
5. 价格和成交额单位为人民币元，成交量为股。按生效日取当时可用的真实后复权因子，不使用未来事件、不从舍入后的复权价反推因子。
6. 最新行情/因子按来源和模式隔离；内容变化追加不可变修订，因子单独变化也审计。相同内容重新采集保留内容批次，并记录真实采集时间。
7. 任务是否复用还取决于输入指纹，包括自选、资产、财报、产业证据、行情修订、配置和算法；明确重新生成时创建新报告修订。

网络获取在数据库写事务之外，验证通过后才提交当前行情、因子与修订。数据表和时间字段见[数据字典](../database/schema.md)。

## 连接、超时和故障切换

| 接入     | 实现                                                       | 超时与重试                                      |
| -------- | ---------------------------------------------------------- | ----------------------------------------------- |
| BaoStock | JDK Socket、共享串行匿名会话、分页与压缩响应、持久请求预算 | 连接/读取 15 秒，IO 失败重连一次                |
| 新浪     | JDK HttpClient；固定 MIT 算法通过 Rhino 在 JVM 中解码      | 连接 10 秒、单请求 20 秒，最多重试一次          |
| Tushare  | 共用JDK HttpClient串行限速                                 | 连接15秒、请求30秒，最多3次尝试，权限拒绝不重试 |
| 多通道   | 整窗切换与能力独立冷却                                     | 默认冷却 30 秒，可配置                          |

固定解码器只接受编码字串，不执行远端返回的脚本，禁用 Java 类访问并限制执行时间。[第三方声明](../../THIRD-PARTY-NOTICES.md)

## 状态与检查

`GET /api/v1/market/providers` 只读返回模式、范围、通道状态、日历来源和已入库来源，不触发采集。

| 状态        | 含义                 |
| ----------- | -------------------- |
| NOT_CHECKED | 本进程尚未请求       |
| AVAILABLE   | 最近请求成功         |
| COOLDOWN    | 最近失败，冷却中     |
| RETRY_READY | 冷却结束，可再次尝试 |

通道状态是进程内最近观测，不代表上游永久可用；重启后重新统计。已入库数据的来源和采集日期与当前通道是否连通分别展示。

### 按通道定位和恢复

工作台“行情通道”分为“通道原因与处理”“通道测试”“能力对照”“已入库数据”。先选择实际通道，再按能力判断，不能把整条来源统一标成受限。五项能力的最近成功、实际失败时间与冷却分别记录；没有证据就保持空，刷新不探测。进程重启会清空临时观测，但不会删除已有行情或持久访问保护。

| 通道           | 常见误读                     | 实际处理                                                                                                        |
| -------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 交易所公告日历 | 股票/指数“不支持”也算故障    | 只读取已核验2024—2026年度规则；范围外补充官方年度通知和测试，或使用其他真实日历                                 |
| BaoStock       | 10001011等于免费接口不开放   | 这是黑名单拒绝；先核对官方待释放时间、日请求数和并发数，不能仅凭代码判断究竟是超量还是并发                      |
| 新浪           | 指数不支持等于个股也受限     | 个股日线含同源因子；指数缺可靠成交额，由其他能力源接替。缺因子、日期不齐和解码失败分别处理                      |
| 东方财富       | 能取指数就能取所有历史和因子 | 现有指数仅沪深300；截面为独立能力，收盘16:10后采集。未归档历史不能用当前名单回填；个股历史/因子需另外实现并验证 |
| Tushare        | 页面没有卡片等于上游拒绝     | 查看未进入路由的配置说明：缺Token为NOT_CONFIGURED，未选择为DISABLED。启用后再分别核验接口权限                   |

BaoStock恢复步骤以[官方访问规则](https://www.baostock.com/blacklist)为准：每日请求不超过5万次且不可并发连接；自然年首次冻结6小时，多次限制按本年累计次数×6小时增长。页面待释放时间为空时，官方建议等待5分钟再查看；其他情况通过官网QQ群联系管理员。该时长是官方规则，不从本机旧记录自行推算当前解封时间，也不保证时间一过就一定恢复。

确认上游允许恢复后，维护人员记录核对依据再恢复本机访问，先用单标的短窗口核验，成功后继续串行同步。未确认前保留保护；不要删除记录、换节点或并发试探。页面展示原始拒绝时间和代码，不将该时间更新为当前查询时间。

DNS失败查DNS，正文超时查网络与读取截止，EOF/Socket重置查连接提前关闭；这些证据均不能直接证明付费不足。只有明确记录HTTP 403/429，才解释为已收到拒绝/限流；公开截面持久冷却仍显示原来的截止时间。新浪缺失字段、复权因子不足、日历区间不足和解码失败保留具体诊断码。泛化旧记录无法补造当时根因，需按任务编号及时间查原日志。

`GET /api/v1/market/providers` 新增 `inactiveChannels`；能力对象新增 `lastFailure`。`GET /api/v1/market/providers/baostock-policy` 新增 `accessCode`、`accessObservedAt`。它们均只读，不含Token、不改变保护，也不发起探测。

### 显式通道测试

管理员在“通道原因与处理”点“测试此通道”，或直接切换“通道测试”。选择已配置通道、基础能力及已完成交易日，再点“测试通道”。打开页面、切换选项和刷新状态都不会发起测试。PUBLIC保留管理员、会话、CSRF及来源COLLECT许可检查。

`POST /api/v1/admin/market/providers/test` 接收一个对象，例如：

```json
{"channel":"EASTMONEY","capability":"INDEX_DAILY","date":"2026-11-12"}
```

基础能力只有TRADING_CALENDAR、STOCK_DAILY、INDEX_DAILY。日历核验一个日期的明确开休市状态；股票固定600000.SH，指数固定000300.SH，核验一日原价、因子和量额。因供应商协议可能分别取得价格与因子，网络请求数不保证只有一次。不提供任意URL、批量回填或收费展示权限的绕过入口。

结果区分SUCCESS（本项样本通过）、FAILED（实际核验失败）、SKIPPED（因保护、未配置、演示或限频未执行）和TIMED_OUT。成功返回实际来源、返回日期、条数及开休市结果，失败或跳过sample为空。空响应、错来源、缺因子和无效OHLC都不能按连通成功处理。休市或指定日无行情，也不能直接判定网络不通。

全局同时一个测试、无等待队列；每通道60秒最多一次（含本地跳过），前端显示倒计时。20秒未完成即返回超时并请求中断；底层退出前不接收新测试。普通状态读取不会等待网络测试锁。下一次测试时间仅为本机限频，不是供应商解封时间；20秒超时也不是永久不可用的证明。

测试复用当前配置及授权装饰、基础能力冷却、BaoStock持久保护、串行会话和日预算。不会自动切换备用来源，不清除访问保护，不更改生产日历窗口，不写行情、财报、报告或数据库结构；仅更新本进程实际能力观测和供应商请求保护资料。BaoStock受保护时只回显旧拒绝证据，不连接上游或改写原始拒绝时间。全市场截面及复权覆盖仍需正式同步验收；一次通过不能证明整条通道或完整历史都可用。

只读实测示例（从根目录执行，可按需要调整日期）：

```bash
bash scripts/tools.sh probe baostock 2026-10-30
bash scripts/tools.sh probe sina 2026-10-30
bash scripts/tools.sh check
```

probe 不访问数据库缓存，新浪探测明确跳过不支持的指数。verify-real 和 replay 会提交任务、写入业务库，详见[脚本目录](../../scripts/README.md)。当前验证与限制见[版本与验收](../verification/README.md)。

## 免费财报与市场截面

- 财报由 Java HttpClient 直接读取东方财富公开的合并利润表、现金流量表，无需 Token。每次取最近 20 期累计报表，按证券与报告期匹配，不使用单季度数据替代累计数据。营收、归母利润和经营现金流单位为元；同比及毛利率为小数。
- 公告只有日期时，最早次日可用；供应商修订时间更晚则从修订次日开始，缺少修订日期则从抓取时间开始。原始响应与内容指纹保留，重复内容不产生新版本。免费数据的公告版本未核验，不作为严格时点回测样本。
- 财报采集结果按证券/业务日记录，成功缓存 6 小时，失败冷却 2 分钟；失败保留已有数据，不生成模拟财报，也不阻断已有行情的研究报告。报告冻结本次采集状态。
- 沪深市场截面按配置路由 BaoStock 或 Tushare，同源单日全量日线与同日证券清单交叉核验，排除指数、基金及 B 股；明确停牌与未知缺口分开统计。完整收盘截面缓存，部分覆盖可重试，15:30 前不缓存当天收盘截面。
- 截面和原始证据追加不可变内容修订，报告引用具体快照 ID。范围为 `SH_SZ_A`，不包含北交所。只有覆盖完整时标记本范围 COMPLETE，不能据此宣称全 A 完整。

## 按能力切换与Tushare研究数据

五项能力分别为交易日历、个股日线、指数日线、沪深截面、复权事件。每个供应商的每项能力独立记录最近观测与冷却；通道页显示UNSUPPORTED表示代码没有该能力，不会为它反复发送失败请求。AVAILABLE只是最近成功，支持声明也不等于账号权限已具备；返回ACCESS_RESTRICTED时保留访问保护，不换主机或并发连接规避限制。

Tushare基础行情和研究数据共用一个限速客户端，串行间隔至少1300ms、重试有界；权限错误直接失败，不反复重试。研究截面使用指定业务日的 `bak_basic` 历史清单配合 `daily`、`suspend_d`，不以今天的stock_basic代替历史名单。分页去重并检查实际日期，截面整批路由，同源因子不足不能从另一家拼接。

历史清单bak_basic从2016年起提供，每次最多7000条并需要相应账号权限，详见[Tushare历史每日股票列表](https://tushare.pro/document/2?doc_id=262)。日线的成交量由手换算股、成交额由千元换算元，规则以[Tushare日线](https://tushare.pro/document/2?doc_id=27)为准；[复权因子](https://tushare.pro/document/2?doc_id=28)和[停复牌](https://tushare.pro/document/2?doc_id=214)单独核验。盘中停牌记录不直接当作全天停牌，因子只覆盖有实际数据的日期，不把首条因子之前补成1。

配置TUSHARE_TOKEN并将tushare列入MARKET_CHANNELS后仍须实际具备上述接口权限。未配置时组合模式明确跳过；BaoStock受限、另一通道能力不支持或权限不足时，仍会如实显示缺失，不回退演示数据。本轮固定输入回归验证不等于真实账号已连通。

## 证券目录、指数与公网许可

自选搜索使用已登记主数据及东方财富固定域名目录，选中后服务端重新核验A股市场与代码。目录失败保留已登记选择项，不接受伪造名称直接补库。目录有短期缓存、并发上限及响应字节/正文读取截止；它不是价格来源。

EastmoneyIndexProvider只提供白名单沪深300指数日线，按年分页，成交量从手换算股，指数因子为1；不宣称支持个股复权、日历或全A截面。HTTP正文使用流式大小上限及独立读取截止，不依赖只覆盖响应头的超时。固定响应与超时场景已测试，当前主机真实上游读取未成功验证，不能据此宣称备用通道已恢复可用。

PUBLIC逐来源检查COLLECT、DISPLAY、EXPORT、DERIVED_REPORT及有效日期。当前没有真实授权记录；数据商权限、访问限制与系统授权登记分别展示。手工登记是操作方声明，不能替代合同或把免费可访问等同于可商用。登录、空白自选及自己的任务状态仍可使用。

## 免费全市场截面与自然归档

EASTMONEY现有指数能力之外，新增独立研究截面适配器。收盘16:10后按以下顺序执行：新浪当前A股目录与独立总数分页核验 → 东方财富带日期报价分页 → 东方财富明确起止时刻的停复牌 → 交叉匹配并归档。报价大目录包含历史退市行，不能直接用其总数作为在市分母。原始目录、行情和停牌页及各自来源、日期均保留；价格来源仍为EASTMONEY，目录来源SINA不能被隐藏。

## BaoStock 免费节点运行约束

BaoStock免费节点和会员通道不是“有数据/无数据”的区分；会员套餐不应被用来解释免费接口尚未接通。官方访问规则见 [黑名单与访问限制](https://www.baostock.com/blacklist)：免费节点每日不超过5万次，不允许并发连接；10001011为黑名单限制，并非付费权限不足。

行情与研究路由现在注入同一 `BaoStockClient` Bean，持久会话全程由 `.runtime/baostock/session.lock` 互斥；单独工具或第二进程若持有同一目录连接，返回 `BAOSTOCK_SESSION_BUSY`，不另建并发连接。锁只保护同一项目运行目录，不能约束同一出口IP下其他项目、容器或机器。客户端串行发送，帧间至少250ms；登录、分页及失败重试都在发送前计入 `.runtime/baostock/usage.json`。

默认上海自然日预算40000，配置 `BAOSTOCK_DAILY_BUDGET` 范围1—45000，留出供应商5万次上限余量。重启不重置，跨上海午夜首次请求写入新日计数；损坏、未来日期、写盘失败均停止请求，不默认为0。未发送成功的预占也不退回，以防上游实际已收到。预算只能记录本项目请求，不是供应商同一IP总量。跨进程会话锁先于Socket取得，Socket关闭后释放；请求任务取消在发送和节流时检查。

工作台“行情通道”单独展示本机预算和访问保护，接口 `GET /api/v1/market/providers/baostock-policy` 只读，不触发采集，也不解除 `.runtime/baostock-access.json`。保护开启表示此前已观察到拒绝，不能解释为刚刚联网确认仍受限；自动冷却不能替代官方解封确认。未确认恢复前保留保护，不更换主机、删除记录或并发请求试探。

已适配能力：交易日历、沪深股票/指数历史日线、复权因子、指定日期证券清单及沪深截面。成交额历史均值、均线广度和新低数量应基于足量真实历史计算，不能因没有付费指标就永久留空；现有历史预热命令继续复用缓存、按交易日串行补采。目录与北交所覆盖仍需逐项核验。BaoStock行业分类不等于PCB/液冷细分主题名单，公司业绩预告不等于机构预测。财报目前继续使用东方财富免费累计报表；尚未添加BaoStock财报金额映射，不把现金流比率换成金额。本轮改造不改算法、不重写旧报告、不声称已完成真实上游恢复。

## 收盘任务的时间边界

真实模式当天日报/周报最早上海15:30后允许入队；这是最低提交时间，不保证供应商此时已发布。盘前、盘中应明确选择前一已完成交易日，不把前一日行情冒充当日。演示模式不受该时间门槛约束，历史交易日补跑不受影响。

若行情整窗采集失败，阶段明细公开证券、日期、缓存/应有条数及受控通道状态；任意上游响应、密钥和内部异常仍只在日志定位。阶段失败且核验分母为0表示尚未完成核验，并非检查通过。旧任务保持原始持久记录，页面可引用整次任务已有的具体错误解释早期泛化阶段提示。

## 故障诊断的阅读方式

任务与通道共用 `FailureDiagnostics` 分类，页面依次展示原因、影响、建议操作和稳定诊断代码。任务旁保留任务编号、阶段和发生时间，HTTP失败保留requestId。新增失败阶段把诊断冻结在阶段JSON中；旧任务只解释已保存的受控代码，不补造当时没记录的网络原因，也不当作当前连通性探测。

分类包括访问保护、请求预算、连接占用、控制记录异常、DNS、连接、读取超时、TLS、HTTP状态、响应结构/复权/窗口校验、授权准入、能力不支持、冷却、未归档历史和收盘未就绪。HTTP 429、401/403及其他状态只在实际响应记录明确时解释；没有状态时说明证据不足，不猜测限流或付费权限。多通道失败保留各通道的分类，不能只写“全部不可用”。未知异常明确为“原因尚未分类”，携带定位编号交给维护人员排查。

本机保护记录不会因展示建议而删除，建议也不等于自动重试；历史证据和当前来源状态继续分开。公开信息不包含供应商原始正文、URL、Token或堆栈。浏览器网络错误、无效响应及超时也分别解释；写请求超时只能表示未收到确认，先查询是否已受理，避免重复提交。

## 供应商数字错误码

BaoStock的 `error_code/error_msg` 在协议层先判断，非零业务码使用独立异常，不能当普通IO断线重连。权限、登录数、参数、黑名单及未收录的新数字码均停止本次请求；真正未取得响应的IO故障仍只允许原有有界重连。错误不因关闭Socket或切换通道丢失数字码。

## 面向用户的行情失败摘要

主提示按股票名称、实际缺失日期、本地窗口最新日期和补采结果说明，不再拼接通道代码。缺失日期来自本次缓存与交易日历集合比较，不从条数或当前时间猜测；本地记录数齐全而强制刷新失败时，不称为缺日。历史日期不齐、陈旧和空响应分别解释，不将“来源已返回数据但日期未齐”当网络断开。未参与能力的日历或指数来源显示正常跳过。

旧任务保留原始持久错误，仅在页面转换成白话，缺失日期当时未保存就明确说明未记录。原始窗口、错误码和阶段技术信息默认折叠；新失败按当时证据形成摘要，历史报告不改写。


## 数据使用许可页面怎么读

“产品与账号 → 数据使用许可”是条款与授权依据的登记台账。页首按服务端实际配置说明当前是否强制检查，未启用时不会因“未登记”拦截使用；PUBLIC始终强制检查，LOCAL也可通过配置显式开启。不开启检查不代表已经获得供应商授权。

来源以中文名称和卡片展示：未登记表示没有依据记录；登记已过期表示有效期结束；尚未生效表示未到起始日期；已登记只表示管理员填报，仍需自行核验。登记状态与行情故障分开，连接、接口权限及缺日等问题到“行情通道”查看并测试。原始来源代码和条款依据可展开查看。

登记表单默认收起。准备对外提供产品时，管理员按实际条款依次选择来源、允许用途、依据链接、条款定位和有效期后保存；保存保留修订，不开通接口、不购买会员、不自动获得授权。密码与Token仍只放在本机私密配置中。
