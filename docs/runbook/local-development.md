# 运行维护

首次启动见[项目首页](../../README.md)，环境变量见[配置说明](configuration.md)，构建检查见[构建与测试](build-and-test.md)。本页只说明日常维护、数据保护和故障定位。

## 服务与生成目录

| 内容                 | 默认位置 / 端口                   | 说明                                                   |
| -------------------- | --------------------------------- | ------------------------------------------------------ |
| 本机 MySQL | `127.0.0.1:3306` | 当前业务库，独立MySQL进程；不由Docker启动 |
| 可选开发MySQL容器 | `127.0.0.1:3307` | 非默认运行方式，显式选择后才使用 |
| 后端                 | `127.0.0.1:8080`                  | Java 21；健康端点 `/actuator/health`                   |
| 前端                 | `127.0.0.1:5173`                  | Vite 本机开发服务                                      |
| 日志、运行副本、备份 | `.runtime/`                       | 本机文件，不进入源码包                                 |
| 源码交付包           | `artifacts/alphascope-source.zip` | 由开发工具生成                                         |

本机开发服务通过启动终端的 Ctrl+C 停止；Docker应用使用 `bash scripts/run-docker.sh stop` 停止。

本机数据库设置及迁移步骤见[本机MySQL](local-mysql.md)。普通业务启动无需Docker；以下隔离恢复功能是独立的可选能力，仍需要Docker。

## 数据库备份与恢复

推荐使用项目工具，自动读取.env，不把密码写入命令参数或日志：

```bash
bash scripts/tools.sh backup
bash scripts/tools.sh verify-backup
```

`backup` 在MySQL只读一致性事务中同时导出表结构、数据和指纹，包含Flyway历史；压缩SQL与manifest保存到 `.runtime/backups/`，目录权限700、文件600。随后启动只属于本次验证的 `mysql:8.0.40` 隔离容器，实际导入并逐表比较结构、列和数据指纹，成功才生成verified标记与 `latest-success.json`。不下载镜像，须预先准备Docker及该镜像；验证失败保留既有成功备份，不报告已验证。

导出和指纹使用同一一致性快照，TIMESTAMP按UTC会话导出和恢复，DATETIME仍保持业务值；JSON数字按精确十进制核验，文本用UTF8十六进制避免转义破坏。当前工具面向本项目InnoDB表，不包含外部服务、用户授权、存储过程或数据库级权限。备份时不要并发修改表结构。

开启 `BACKUP_ENABLED=true` 后应用按上海时间每天02:00执行；错过计划会在应用恢复运行后补做。`latest-run.json`记录最近定时/服务调用成功或失败；`latest-success.json`只指向实际验证成功的备份。默认保留14天，至少7天；只清理工具命名的过期备份、清单与标记，并始终保留最近两份已验证备份，其他历史手工备份不删除。

生产恢复必须先停后端，核对备份SHA256和manifest，并先执行隔离恢复验证。准备空的目标数据库后，用数据库客户端交互输入密码导入解压SQL；包括匹配的 `flyway_schema_history`，启动兼容版本应用。下面仅为手工灾难恢复入口，不会由定时备份自动写回当前库：

```bash
gzip -dc .runtime/backups/alphascope-实际时间-标识.sql.gz > .runtime/backups/restore-reviewed.sql
mysql -h 127.0.0.1 -u alphascope -p alphascope < .runtime/backups/restore-reviewed.sql
```

当前开发基线新增结构同步默认仍要求新鲜验证备份。仅在用户明确选择本次不备份时，使用 `bash scripts/tools.sh upgrade-schema-direct`：要求BASELINE/1和无活动任务，只执行基线中受控的新增结构，并逐表核对原字段指纹。它不创建备份、不修改旧行情/报告、不关闭Flyway校验。空库仍直接执行唯一V1，见[数据库入口](../../database/README.md)。

禁止把 `docker compose down -v` 当作普通重启步骤，它会删除持久化数据卷。禁止通过删除历史表或修改校验和掩盖结构差异。

## 日志与任务收尾

应用滚动日志为 `.runtime/logs/alphascope.log`，单片20MB、历史14天、归档总量上限1GB。每行保留requestId、jobId、stage及provider，便于区分HTTP请求、任务和供应商故障；不记录Token和上游完整正文。开发启动终端日志另行保存在运行目录，不属于业务滚动归档。

任务心跳只表示线程仍在运行。阶段有独立硬截止，实际完成项才更新进度。取消请求先保存到数据库，再中断工作线程；原生网络读取可能等待已有超时后收尾，页面继续轮询，不承诺立即停止所有底层I/O。已提交事务及已生成的不可变报告保留。失联恢复保留先前取消/超时意图，重试沿用原编号，归档原状态与阶段后重新核验输入。

## 日常排查顺序

| 现象                   | 先检查                               | 后续处理                                     |
| ---------------------- | ------------------------------------ | -------------------------------------------- |
| 启动提示 Java 版本不符 | `JAVA_HOME`、JDK 架构和版本          | 选择 Java 21 后重启启动终端                  |
| 后端无法连接数据库     | 本机MySQL服务、端口、专用账号和实际实例    | 先区分本机与可选容器；环境变量不会自动修改已有账号密码 |
| 页面无法读取数据       | 后端健康、8080、前端代理             | 使用页面展示的 requestId 对照日志            |
| 任务排队未执行         | 后台 worker 是否启用、是否有前序任务 | 不把关闭页面当作取消任务                     |
| RUNNING 长时间不结束   | 心跳、阶段硬截止、实际进度和工作锁               | 失联且工作锁释放后才会中断；在页面重试       |
| 行情缺口或通道故障     | 行情通道页、日历、供应商状态         | 核对能力和权限；访问受限时停止探测，未知缺口不能补零 K 线      |
| 评分 UNKNOWN           | 缺失维度与覆盖率                     | 当前全 A 数据未补齐，属于正常的保守状态      |
| 历史报告字段较少       | 算法版本、模式及冻结输入             | 旧阶段没有保存的证据不能事后虚构             |

只读检查：`bash scripts/tools.sh check`。直接接口探测及会写入任务的验收命令见[脚本目录](../../scripts/README.md)。

## 队列与恢复边界

- PENDING 保存在数据库，进程重启后继续消费。
- 执行中及取消/超时收尾每5秒心跳，失联两分钟且工作锁已释放后恢复；已有取消/超时意图保留，否则为INTERRUPTED。
- 页面重试沿用原编号，原失败或中断原因及阶段保存在执行历史中。
- 普通业务失败不无限自动重试，避免持续冲击免费接口。
- 已知上市前区间和供应商证实的停牌分别处理；未知缺口仍失败，不填造行情。
- 电脑休眠期间不会执行计划。研究任务启动补跑默认关闭，可在页面补跑；备份启用后独立按已保存计划检查补做。

业务能力与研究限制见[架构与口径](../architecture/overview.md)，不要用运维配置绕过数据不足保护。

## IDEA 中Java文件大面积标红

若 `record`、`LocalDate` 和 `jakarta.validation` 同时报错，先核对项目SDK和Maven导入结果。终端编译通过并不代表IDEA已成功导入依赖；Maven导入失败时，模块可能残留Java 1.5语言级别。

1. Project Structure → Project：选择能在当前CPU上运行的Java 21，语言级别选21或SDK默认值。Apple Silicon应选择ARM/aarch64版本。
2. Settings → Build Tools → Maven → Importing：JDK for importer选择该Java 21。
3. Maven → Runner：JRE选择同一个Java 21。
4. 从根 `pom.xml` 重新加载整个Maven项目，等待依赖和索引完成；不要只导入backend子目录。

日志出现 `Bad CPU type in executable` 表示所选JDK无法在本机执行。先更换JDK，再重新导入；无需为此改写DTO、替换校验注解或重复添加已经声明的依赖。若从外部修正 `.idea` 后IDEA仍显示旧值，关闭并重新打开该项目再加载Maven。本机SDK名称不写入交付源码配置。

## 运维状态页

左侧“运行检查”通过GET /admin/operations只读展示应有收盘日期、权威日历覆盖、自选与基准的实际行情日期、最后备份及最近尝试、第二存储状态。日历不足不会把旧行情标成最新；旧进程留下的RUNNING/QUEUED文件不会被当作当前实际执行。

备份证明同时检查本机文件、实际SHA256和恢复验证标记；丢失、损坏、超过计划后2小时未完成会明确提示。服务健康UP不能代替这些业务核验。只有点击“创建并验证备份”才提交手动备份，自动执行受BACKUP_ENABLED控制。

第二存储只复制已实际恢复验证的文件，复制失败保留本机成功备份并显示PARTIAL/FAILED；最近成功的副本指针保留。第二位置的实际挂载和独立故障域由部署者提供；同盘副本会明确标出。
