# 产品验收与发布门槛

检查日期：2026-11-13。当前 AlphaScope 0.1.0 为本机内测版本，目标是多用户市场研究产品；暂不部署，尚无 GitLab 仓库。本文是当前产品验收入口，只维护一份现状，不累计历次整改记录。执行证据见[当前验收](README.md)。

## 产品应交付什么

核心流程：确认研究日期与数据范围 → 查看市场和产业链 → 搜索并加入自选 → 同步并跟踪任务 → 按短、中、长期核对个股行动条件 → 阅读冻结报告 → 用后续事实和历史样本验证。

产品输出必须说明证券、研究日期、实际行情日期、来源、证据与失效条件。条件式行动计划不等于可成交委托；长期经营假设和估值缺失时，不能只凭技术价位给出长期买入结论。研究复算一致和规则有效性分别验收。

## 本轮发现并修复的共性问题

| 问题 | 产品行为与检查方式 |
| --- | --- |
| 默认自然日容易落到盘前或无收盘数据的日期 | 从已保存的权威日历确认最近收盘日；查不到时明确提示未确认，不按星期猜测。手动日期和链接日期优先，迟到请求不能覆盖；本期股票行情更新不表示旧市场截面也已更新，历史观察单独标记 |
| 刷新或转发后研究日期丢失 | 研究日期写入链接，支持完整重载和前进后退；提供“最近收盘日”显式重选；切换日期只读取，不触发采集 |
| 个股财报等可选接口失败遮住整页 | 主资料、行情、指标、规则、财报和持有计划分别加载与重试；指标失败仍可读价格，财报失败不遮住持有计划 |
| 切换证券、日期或筛选后保留旧查询结果 | 公共资源加载器按查询身份清空旧数据并取消旧请求；只有同一查询刷新才允许保留内容并标明正在刷新或失败 |
| 报告冻结日期与全局日期混淆 | 报告详情不显示无效的日期筛选；进入个股时显式携带本期日期，并说明当前版本回看可能包含后来补录资料 |
| 当前运行状态页面的日期筛选不生效 | 行情通道、运行检查、产品与账号只显示当前状态刷新；帮助与术语不显示日期选择 |
| 修改搜索词或请求失败后还能选中旧候选 | 自选搜索词变化即取消旧请求、清空候选与选择；迟到结果无效；添加时重新检查候选归属 |
| 图表可能把缺失因子转换为0 | 验证原价、复权因子、同源口径与演示范围；不合格记录保留缺口并说明，不生成虚假零价或跨缺口连线；首页可比涨跌也校验双方因子与来源，标出比较起日 |

## 按完整流程验收

“已验证”只覆盖下列具体范围，不表示不存在缺陷。每次更改优先执行受影响流程；共享入口、认证、日期、资源加载器或路由改变时，同时执行 LOCAL/PUBLIC 浏览器回归。

| 领域 | 验收条件 | 当前状态与证据 |
| --- | --- | --- |
| 首次使用 | 无私有资料的新账号可通过使用说明找到搜索、自选、初始化和任务进度；空状态可区分无记录与读取失败 | 隔离 PUBLIC 浏览器注册与初始化流程；帮助与术语分别组织，术语原位说明 |
| 市场与自选研究 | 日期可追溯；显示真实范围、来源和时效；单个标的或资料故障不遮住其他内容 | 本轮只读核查确认应有收盘日2026-11-12，5只当前自选与1只基准均FRESH；不把此结果当成全A覆盖证明 |
| 研究结论 | 有效资料才输出参考；缺项、演示、UNKNOWN和未触发分别表达；短中长期前提明确 | 已有三周期与两月量价研究测试；方法尚未完成充分历史效果验证，长期估值与经营假设仍需补充 |
| 报告与验证 | 固定日期、版本和输入可核对；不得用当前资料改写过去报告；历史回看明确资料可得性 | 日报#39为2026-11-12第3版，属于本轮前已保存记录；原报告保持冻结。回看链接明确日期和当前资料版本 |
| 异常与恢复 | 错误有原因、影响、下一步和请求线索；只重试适用能力；页面读取无采集副作用 | 已有结构化错误、供应商原码、任务阶段与本机保护；本轮增加分区重试与竞态测试，不触碰BaoStock限制保护 |
| 显式通道测试 | 管理员手动发起；指定来源禁止备用降级；受保护或冷却时不联网；失败不返回零条成功 | 新增一日基础能力样本、耗时与诊断；20秒截止、全局一个、每通道60秒限频，基础与PUBLIC越权测试通过；不以单次通过证明持续可用 |
| 身份与私人数据 | PUBLIC有登录、CSRF、角色及租户隔离；退出后旧资料清空；后端拒绝越权 | 已有双账号、自然键与私有表隔离测试；本轮重跑隔离PUBLIC浏览器，不把本机IP限制作为身份机制 |
| 布局与可读性 | 页面主操作清楚；日期筛选确实生效；桌面与窄屏无横向页面溢出；状态可解释 | 14个模块桌面与手机布局回归；报告分栏分类、三周期研究、帮助与术语独立；具体结果见当前验收 |
| 工程与交付 | 一个源码版本、一份SQL；构建、格式、类型检查、流程回归可重跑；发布资源一致 | 唯一V1、Mapper XML、Service接口及实现、统一Result；本机MySQL默认连接；生产JAR、源码ZIP、指纹和GitLab CI已具备本地验证路径 |

## 仍阻止正式对外发布的条件

| 优先级 | 尚缺条件 | 完成标准 |
| --- | --- | --- |
| P0 | 可核验的数据用途授权 | 核对供应商实际条款或合同，确认采集、展示、派生报告、导出的许可范围和有效期；PUBLIC无许可继续阻断，不能用手工声明代替授权 |
| P0 | 后端依赖漏洞扫描结果 | 在有网络的受控环境或Runner完成既有OSV阻断检查，处置发现项；SBOM和既有npm结果不替代本项 |
| P1 | 行情连续性与供应商故障恢复证据 | 先确定收盘数据截止时间与允许延迟，跨连续交易日记录成功、延迟、重试和人工恢复；单日FRESH不等于服务保障；BaoStock受限不能绕过 |
| P1 | 历史范围与研究效果验证 | 补齐有来源、日期和覆盖证明的历史数据，区分全A、沪深范围与固定样本；确定样本规模、样本外窗口、基准、成本与可成交假设，再判断方法效果；缺条件时继续UNKNOWN |
| P1 | 正式规模与恢复验收 | 确定用户数、任务量、存储预算和响应目标，做持续容量及故障恢复验证；已有24个并发只读请求只是冒烟。按当前用户要求不新增业务库备份，不能宣称已满足生产恢复目标 |
| P1 | 远程交付与升级回滚实际执行 | 提供GitLab仓库与Runner后执行CI和安全扫描；在隔离环境演练安装、升级与回滚。当前未推送、未部署，不把本地脚本当远程执行证据 |

这些条件满足前，适合继续做本机、多账号研究内测，不标记为可收费公开运营或已验证收益的交易产品。

## 后续改动的完成定义

1. 先说明用户从哪里进入、看什么结果、下一步去哪里；同步核对其他同类页面，避免只改截图中的一个位置。
2. 查询必须带明确身份；异步切换、失败、空资料、旧资料、重复提交和退出登录都要有确定行为。
3. 原始证据、当前回看和冻结报告分别验收；任何缺项不能被补成0、正常或完整覆盖。
4. 补充有意义的回归场景，并执行格式、类型与生产构建；共享流程变化重跑隔离浏览器及窄屏布局。
5. 更新本页现状和[当前验收](README.md)的证据；检查JAR、源码ZIP和发布指纹与本次源码一致，再交付结果。
