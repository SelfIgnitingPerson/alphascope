# 架构与业务口径

工程分层和修改规则见[项目约定](project-conventions.md)，具体代码位置见[后端导航](../../backend/README.md)、[前端导航](../../frontend/README.md)。本页说明当前业务如何协作。

## 运行结构

```text
Vue 工作台
  ├─ GET → Controller → Service接口 → ServiceImpl → Mapper/XML → MySQL 当前视图 / 已保存报告
  └─ POST 任务 → MySQL 持久队列 → JobWorker → 私人研究消费者 / 共享采集消费者
                                         ├─ 行情与日历供应商
                                         ├─ 指标、主题、规则
                                         └─ 报告、冻结输入、本地通知审计
```

后端为模块化单体，没有独立行情服务。持久队列、互斥和业务数据统一使用 MySQL。

## 一次日报的执行

| 阶段         | 职责                                   | 失败时的行为                 |
| ------------ | -------------------------------------- | ---------------------------- |
| FORECASTS | 采集自选公开EPS预测，按实际观测时刻归档 | 失败保留已有快照，不倒填历史 |
| CALENDAR     | 获取覆盖分析窗口的权威日历             | 缺失或无效则停止             |
| THEME_MEMBERS | 导入业务日已公开可用的固定同业样本 | 来源冲突或成员损坏则停止，不覆盖旧版 |
| MARKET_SYNC  | 获取或复用完整同源价格、因子和停牌证据 | 整窗切换通道，仍不足则停止   |
| DATA_QUALITY | 核对业务日数据、上市与停牌状态         | 未知缺口不继续计算           |
| RESEARCH_DATA | 同步自选财报与沪深市场截面 | 保留失败状态与已有证据，不补造数值 |
| MARKET_OBSERVATION | 从已保存沪深历史截面与真实因子形成分项观察 | 私人研究只计算已有证据；缺项保留空值，不等待整批历史补齐 |
| INDICATORS   | 批量读取历史和基准，分窗计算指标       | 缺少可计算证据时记录不足     |
| SCORE_RULES  | 主题强弱、市场覆盖和风险规则           | 缺项不生成虚构分数或触发结论 |
| REPORT       | 生成规则版或经校验的模型摘要，冻结输入 | 模型不可用时回退规则摘要     |
| NOTIFICATION | 本地通知审计及去重                     | 保留任务和错误记录           |

任务以业务日期、配置范围及输入指纹识别可复用结果；force 明确生成新修订，失败重试沿用原任务编号并归档历次执行。任务状态和异步接口见 [REST API](../api/endpoints.md#任务提交与重试)。

## 价格与指标

| 项目           | 口径                                                     |
| -------------- | -------------------------------------------------------- |
| 原价与因子     | 分开存储，必须同源；因子按生效日取值，不使用未来除权事件 |
| 分析复权价     | 原价 × 当日因子 ÷ 分析日因子；OHLC 同步换算，量不复权    |
| MA             | 包含分析日的最近 N 个有 K 线交易日                       |
| 量比           | 当日量 / 前 20 个有 K 线交易日平均量，均量排除当日       |
| ATR14          | 首 14 个有前收盘的 TR 均值，之后 Wilder 平滑             |
| RS20           | 标的区间收益比 / 沪深 300 同期收益比 − 1，日期不齐时为空 |
| 20 日新低      | 与分析日前 20 个有 K 线交易日比较，不将当日纳入前值      |
| 连续日均线规则 | 前日均线先换算到同一复权锚点再比较                       |

历史指标先按标的与基准批量加载，再在内存中分窗，避免逐日重复读取两年行情。算法实现在 `IndicatorCalculator`，数据状态与输入哈希记录于指标快照。

## 主题、财报与规则

主题按业务日有效成员计算等权收益，不能直接平均股价；覆盖率不足不评分。使用有公开披露依据的固定PCB制造与液冷机组研究样本，单独记录来源与可用时点，不倒填旧手工归属、不自动加入自选。样本覆盖不等于整个产业或全市场，详见[同业研究手册](../runbook/theme-research.md)。

财报由 Java 直接采集东方财富公开合并利润表与现金流量表，也支持手工登记。同报告期/类型采用截至业务日可用的最高版本；免费源仅提供日期，按公告与供应商修订日期的次日起使用，无修订日期则从抓取时起可用。保存原始响应、来源 URL、抓取时间和内容指纹。该源未核验原始公告版本，不作为严格时点历史回测样本。毛利率等比例以小数存储，现金流按相同类型、相同报告期比较，不混用单季度与累计值。

规则将可用事实保存为证据，并区分已触发、未触发、证据不足、不适用和模拟状态。默认自选研究模式将持仓集中度标为不适用，不要求录入个人资产。主题背离至少需要两只有效成员，且同一主题的记录覆盖日历中最近三个交易日；逐日验证成员数、覆盖率及数值，不能把离散日期或不同主题拼成连续证据。成员不足、记录不足时冻结具体诊断，不倒填历史。

## 报告与追溯

- 当前报告冻结行情、累计财报、规则、沪深截面、样本定义与成员、日历、规则阈值和分析结果，展示连续三日主题评分、排除自身的20/60日同业收益相关及控制沪深300后的相关性。研究建议分事实、待验证解释、具体核查与改变判断的条件，不依赖 AI；“量子纠缠”仅为类比，实际采用经典统计。未触发、证据不足和不适用分别统计；均线与前20日低点只是历史观测值。
- 模型仅解释已有输入；结构、引用白名单和数字字面量校验不通过时重试一次，再回退规则版。
- 报告修订只新增；保存完整冻结输入、来源批次、输入哈希、算法/提示词版本及配置范围。
- 行情时间、采集时间、生成时间分别保存，读取旧缓存不伪装成新采集。
- 行情最新视图按供应商和真实/模拟模式隔离，实际内容变化另存不可变修订。旧阶段未保存的历史值不事后编造。

## 本机访问约束

LOCAL服务与本机容器入口只绑定回环地址；PUBLIC使用登录会话、角色、租户、HTTPS来源和CSRF独立校验。不信任客户端转发地址授权。请求生成服务端 requestId 供日志定位。模型来源文本按不可信内容处理，不具有系统指令权限。

运行方式见[运行维护](../runbook/local-development.md)，依赖版本和构建规则见[构建与测试](../runbook/build-and-test.md)。

沪深观察与机构预测的计算、时点及访问受限边界见[运行手册](../runbook/market-observation.md)。报告冻结分项结果、业务时点预测及 `marketAcquisition` 的获取方式、区间和原采集时间。已结束业务日允许校验复用真实历史，同业成员使用140个日历日窗口；不改写采集时间，不绕过访问保护。当前算法统一由 `common/config/ResearchVersion.java` 管理，完整全A评级仍需独立满足范围和规则。

## 能力路由、质量与执行控制

基础行情和研究截面采用两套明确SPI：MarketDataProvider负责日历/个股/指数；ResearchDataProvider负责沪深截面/真实因子，两者复用同一供应商配置和受控客户端。每项能力独立冷却，某通道日历失败不阻断该通道的健康个股能力。整批截面失败可换源；同一个分析窗口的价格与因子必须同源，不能跨源补洞。

JobExecutionControl统一阶段边界、持久取消、硬截止、MDC和进度；StageQualityInspector只核查已存证据，分别产生执行状态与质量状态。行情核心阶段仍在必要证据失败时停止，可选研究采集可以执行成功且数据不足。已确认停牌和上市前区间为不适用，不被当作缺失技术指标；旧任务没有核验结果就保留null。

公共ExecutionContext在耗时采集边界提供取消和实际进度检查，阶段退出清除线程上下文，避免复用线程污染。重试重新核验当前输入，已有可信缓存可复用，不能因为旧阶段成功而跳过输入变化。当前保留单队列工作进程，不虚构并行采集收益。

运维模块将一致性备份、指纹、隔离恢复验证和保留规则集中在DatabaseMaintenance；定时Service和CLI复用它，不维护第二套导出实现。配置集中在AlphaScopeProperties，供应商密钥不进入可打印配置对象。方法统计与局限见[历史研究验证](../runbook/historical-validation.md)。

## 当前职责边界与规则产物

JobService负责提交、互斥、领取、心跳、失联恢复与原子完成；ResearchPipelineService编排业务阶段；JobSnapshotService集中装配确定性输入指纹。每次流水线使用局部Run上下文，不把业务日期和质量列表泄漏到另一任务。规则产物以RuleCode/RuleCatalog的完整清单、当前版本和适用性核验，不按查到的行数缩小分母；不适用也需有明确记录。

DatabaseMaintenance是维护门面，导出/指纹、隔离恢复、保留策略、受限文件操作、第二存储及开发基线同步分别由专职组件实现。SQL维护仅用于明确的运维动作；普通业务SQL仍通过Mapper/XML。

历史验证新增不可变修订重建与实验注册表，实验捕获使用一致读，复算不读当前配置。市场五维规则及范围门槛见[评分方法](../runbook/research-scoring.md)，时点与实验边界见[历史研究验证](../runbook/historical-validation.md)。

## 独立验证执行链路

ValidationTaskController接收冻结请求，ValidationTaskService负责队列、归属、停止意图和最终发布；ValidationDataService在短期一致读中读取资料；ResearchValidationService在事务外执行逐日计算。TechnicalEvidenceCalculator由生产指标、信号及回顾共用，ResearchValidationVerifier从价格和冻结规则核对指标、规则及统计四层。ValidationSummary显式裁剪大证据，完整原文只在单独下载接口读取。不存在同步GET重计算入口。

连续日线更新由ScheduledUpdateService统一选择最近已收盘交易日，收盘提交和启动/休眠补跑共用持久队列；自动重试有每日范围预算，用户取消不自动重建。交易所年度日历仅覆盖已核验资源，指数与股票按能力分别路由，仍保持每个证券窗口原价与因子同源。详见[配置](../runbook/configuration.md#连续日线更新)。

## 共享采集与个人研究

`MARKET_HISTORY`、`MARKET_UNIVERSE`、`MARKET_FULL` 由管理员空间的独立共享消费者执行；DAILY/WEEKLY由私人消费者执行。心跳、截止与验证也各自独立。长历史任务不再持有私人消费者；供应商共享客户端仍串行、限频及遵守持久访问保护，增加消费者不等于增加供应商并发。

`MARKET_FULL` 先核对三所同日证券目录、实际行情和停牌状态，再读取同来源历史与因子计算20/60日广度，保留完整原文、分页和指纹。没有历史目录时不能拿今天名单回填过去；因子缺失不能填1。工程入口存在不等于真实全A历史已完整，评级仍须逐项满足门槛。

证券同步先取得有来源的上市/退市日期，窗口不包含上市前或退市后的交易日；来源无法核验时明确阻断，并可由管理员以公开公告补录。北交所旧精选层日期不能自动视为北交所上市日。

任务中心按类型筛选。失败重试是同一任务的新执行，原失败、来源和阶段保留在执行历史，成功后主列表显示当前状态；只有明确的新报告修订、输入版本变化或新业务任务才建立另一主记录。
